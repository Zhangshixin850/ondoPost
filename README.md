## 限流与请求调度

- 全部客户端共用限流器，在 HTTP 发送层统计下单、撤单、查询、分页、重试和风控请求。
- 发送间隔至少为 1 / rps 秒，滚动一秒内请求数不超过 rps。
- rps >= 2 时，普通重报价和后台查询最多使用 rps - 1 RPS，为紧急操作预留容量；rps=1 时全部按优先级共用额度。
- 优先处理到期风控、紧急撤单、成交对冲和未确认写入查询；同级任务按币种轮转。
- 每侧仅保留一个待重报价意图。获得额度后重新检查盘口和风控状态，失效请求放弃并重新计算；签名在实际发送前生成。
- 429 触发全局冷却，遵守 Retry-After；未提供时按 2、4、8、16、30 秒递增退避。行情推送不能提前结束冷却。
- 冷却期间继续接收成交，撤单与对冲保留排队；不确定写入按客户端订单 ID 查询，禁止盲目重发。
